## Milestone 2 - Submission and Upload

Milestone 2 adds the submission and secure chess replay upload functionality.

### User Flow

1. User enters an email address.
2. User selects a `.txt` chess replay file.
3. Frontend sends the submission information to API Gateway.
4. Lambda creates a unique submission ID.
5. Submission metadata is stored in DynamoDB.
6. Lambda generates a short-lived presigned S3 upload URL.
7. The browser uploads the chess replay directly to the private S3 upload bucket.
8. The backend verifies that the uploaded object exists.
9. The submission status is changed to `UPLOADED`.

### Status Model

The frontend supports:

- `UPLOADING`
- `UPLOADED`
- `ERROR`

### AWS Architecture

Frontend:
- Amazon S3 static website

Backend:
- Amazon API Gateway HTTP API
- AWS Lambda
- Amazon DynamoDB
- Amazon S3 private upload bucket

### Security

The chess replay bucket is private.

Users do not receive permanent AWS credentials or direct bucket permissions.

A short-lived presigned S3 URL is generated by the Lambda function for the individual upload.

### Infrastructure as Code

All Milestone 2 resources are defined in:

`infrastructure/template.yaml`

No manually created backend resources are required.

### Milestone 2 Result

The application successfully accepts an email address and chess replay file.

The frontend shows:

Uploaded files are stored in the private S3 bucket and submission metadata is stored in DynamoDB.
